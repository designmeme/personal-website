# TOC 활성 항목 자동 스크롤 설계

## 목적

긴 글을 읽으며 본문을 스크롤할 때 오른쪽 목차의 활성 항목이 목차 스크롤
영역 밖에 있으면, 목차 영역을 부드럽게 스크롤해 활성 항목을 보여준다.

## 동작

- 기존 `IntersectionObserver`가 결정하는 `activeId`와 활성 스타일을 유지한다.
- `activeId`가 바뀌면 해당 목차 링크에
  `scrollIntoView({ behavior: 'smooth', block: 'nearest' })`를 호출한다.
- 활성 링크가 목차의 보이는 영역 안에 있으면 `nearest` 동작에 따라 위치를
  바꾸지 않는다.
- 활성 링크가 위나 아래로 벗어난 경우에만 가장 가까운 경계까지 부드럽게
  이동한다.
- 본문 상단을 나타내는 빈 `activeId`에는 자동 스크롤을 실행하지 않는다.
- `useScrollActive`가 꺼진 목차에서는 자동 스크롤을 실행하지 않는다.

## 구현 구조

- `Toc`이 목차 루트 DOM 요소를 저장할 ref를 소유한다.
- 각 링크는 자신의 ID가 `activeId`와 같을 때 `aria-current="location"`을
  표시한다.
- `Toc`의 effect가 `activeId` 변경 후 루트 안의 활성 링크를 찾아 스크롤한다.

## 오류 및 호환성

- 활성 링크를 찾지 못하면 아무 동작도 하지 않는다.
- 브라우저 기본 `Element.scrollIntoView`를 사용하며 별도 스크롤 위치 계산이나
  타이머를 추가하지 않는다.

## 검증

- 활성 링크가 바뀌면 `smooth`와 `nearest` 옵션으로 스크롤되는 단위 테스트를
  추가한다.
- 빈 활성 ID 또는 스크롤 활성화가 꺼진 경우 호출되지 않는지 확인한다.
- 전체 테스트와 타입 검사를 실행한다.
- 실행 중인 개발 서버의 긴 RSS 글에서 목차 아래쪽과 위쪽 항목으로 이동할 때
  활성 항목이 목차 안에 표시되는지 브라우저로 확인한다.
